# Placeholder copy contract

The MVP renders structure, not product language. Every visible string is a token.

## Token shape

```text
{workspace_name}
{empty_context}
{recent_object_03}
{permission_field_02.description}
```

- `snake_case`, inside single braces.
- Nested description keys use `.description` — one level, no deeper.
- Numbered families are zero-padded to two digits: `_01` … `_24`.
- No locale segment in MVP. A locale map is additive: `t(key, { locale })` later.

## Resolver

`slices/placeholders/index.ts` is the only public entry.

```ts
// slices/placeholders/index.ts
export function t(key: string): string; // '{key}' when unknown, warn once in dev
export function tp(key: string, n: number): string; // zero-pads families
export const PLACEHOLDER_KEYS: readonly string[]; // for tests + coverage check
```

Rules:

1. Pure, synchronous, no state. No `$state`, no context.
2. Unknown key returns `{key}` and emits one `console.warn` per key in dev only.
3. `PLACEHOLDER_KEYS` is the SSOT for coverage tests; a key is either declared there or
   generated by `tp` from a declared family root.
4. Components never inline braces by hand. `<p>{t('welcome')}</p>` — not `<p>{welcome}</p>`.
5. Accessibility strings (labels, `aria-label`, `title`) are tokens too, except the
   generic control words a screen-reader needs to be usable: `Close`, `Remove`, `Add`.
   Those stay literal and are listed in `GENERIC_LABELS` so the exception is auditable.

Families are enumerable. A category or capability _name_ is generated with `tp`, but the
descriptive fields around it are declared, so tests can assert coverage both ways.

## Coverage test

`slices/placeholders/index.spec.ts` asserts:

1. Every key in `PLACEHOLDER_KEYS` returns a value wrapped in braces.
2. `t('definitely_not_a_key')` returns `{definitely_not_a_key}`.
3. `tp('capability', 3)` returns `{capability_03}`.
4. A grep-style source scan finds no literal `{` + word + `}` inside `slices/**/*.svelte`
   outside the resolver (guards hand-inlined tokens).

## What placeholder mode must still get right

Placeholders are copy, not an excuse for weak UI:

- Truncation, wrapping and overflow are real; long tokens are a natural stress test.
- Disabled controls need a _reason_, and the reason is a token like `{commit_disabled_reason}`.
- Empty, no-match and error states are distinct, never collapsed into one message.
- Numbers (counts, timestamps, progress) are real values formatted by `Intl`, not tokens.
