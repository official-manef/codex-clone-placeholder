# Placeholder copy contract

The MVP renders structure, not product language. Every visible string resolves through one
copy table, and the resolved value is human-readable label text.

## Copy contract

```text
workspace_name              → Workspace
empty_context               → No objects in this context.
recent_object_03            → Recent object 3
permission_field_01.description → Controls which actions this workspace can ask for.
```

- The resolver returns human-readable label text, never a brace token.
- Keys stay `snake_case` identifiers; they are internal identifiers, not visible copy.
- Nested description keys use `.description` — one level, no deeper.
- Numbered families carry their number in the label: `_01` … `_24` → `Recent object 1` … `24`.
- No locale segment in MVP. A locale map is additive: `t(key, { locale })` later.

## Resolver

`slices/placeholders/index.ts` is the only public entry; `slices/placeholders/copy.ts` is the
copy table (`COPY`).

```ts
// slices/placeholders/index.ts
export function t(key: string): string; // human-readable copy; undeclared keys humanized + warn once in dev
export function tp(root: string, n: number): string; // zero-pads families, then resolves copy
export const PLACEHOLDER_KEYS: readonly string[]; // for tests + coverage check
```

Rules:

1. Pure, synchronous, no state. No `$state`, no context.
2. An undeclared key returns a humanized fallback (`workspace_name` → `Workspace name`,
   `constraint_notice.recovery` → `Constraint notice: recovery`) and emits one `console.warn`
   per key in dev only. The fallback never emits `{` or `}`.
3. `PLACEHOLDER_KEYS` is the SSOT for coverage tests; a key is either declared there or
   generated by `tp` from a declared family root. Every declared key has a `COPY` entry.
4. Components never hand-write visible strings. `<p>{t('welcome')}</p>` — not `<p>Welcome</p>`
   and not `<p>{welcome}</p>`. If a key renders with no `COPY` entry, add the entry; do not
   inline text in the component.
5. Accessibility strings (labels, `aria-label`, `title`) go through the resolver too, except the
   generic control words a screen-reader needs to be usable: `Close`, `Remove`, `Add`.
   Those stay literal and are listed in `GENERIC_LABELS` so the exception is auditable.

## Copy style

- Sentence case for labels and headings; no trailing period on labels, periods on sentences.
- 1–4 words for labels (`Workspace`, `Priority`, `Recent objects`, `Send`, `Stop`).
- Sentence form for descriptions and states (`No results match your search.`,
  `Submit is disabled because the draft is empty.`).
- Neutral and generic: these are structural labels for a demo shell, so no product claims,
  names, metrics or URLs.

Families are enumerable and numbered labels are derived from the family range, so a category
or capability _name_ is generated by `tp`, while the descriptive fields around it are declared
in `COPY`, so tests can assert coverage both ways.

## Coverage test

`slices/placeholders/index.spec.ts` asserts:

1. Every key in `PLACEHOLDER_KEYS` resolves to non-empty copy with no `{` or `}`.
2. `t('definitely_not_a_key')` returns `Definitely not a key`.
3. `tp('capability', 3)` returns `COPY['capability_03']` — `Capability 3`.
4. Family padding still holds past the declared count, and copy (not braces) comes back.
5. A grep-style source scan finds no literal `{` + word + `}` inside `slices/**/*.svelte`
   outside the resolver, and no `.svelte` file renders a brace pattern as visible text
   (guards hand-inlined keys and hand-written copy alike).

## What placeholder mode must still get right

Placeholders are copy, not an excuse for weak UI:

- Truncation, wrapping and overflow are real; long labels are a natural stress test.
- Disabled controls need a _reason_, and the reason resolves through the copy table too.
- Empty, no-match and error states are distinct, never collapsed into one message.
- Numbers (counts, timestamps, progress) are real values formatted by `Intl`, not placeholders.
